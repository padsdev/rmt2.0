# Experimental Benchmark Workflow

This directory contains the offline, reproducible benchmark workflow for the 17 local Java target projects used in the TCC experimental phase.

## Files

- `benchmark-projects.csv`: manifest of the benchmark inputs.
- `run-benchmark.sh`: runner that uploads each project through the existing RMT API, captures M4 shadow JSONL outputs, and invokes the M5 evaluator.
- `runs/<run-id>/`: run-specific artifacts generated by the runner.

## Preconditions

- The 17 ZIP projects exist under `target-projects/`.
- The local RMT stack is already running.
- AI integration is enabled only in shadow mode through the existing runtime configuration.
- Redis and LocalStack state should be clean for a fresh benchmark run, or at minimum isolated from previous uploads of the same ZIP files.
- No concurrent benchmark upload is writing to the same shared M4 JSONL export file during the run.
- The runner now filters the shared M4 export by runtime `project_id`, so cumulative export history does not contaminate per-project artifacts.

Typical stack startup:

```bash
./rmt.sh all
```

Or, if you prefer local Spring Boot processes:

```bash
./rmt.sh dev
mvn spring-boot:run -pl project-sync-bff
RMT_AI_ENABLED=true mvn spring-boot:run -pl detection-and-refactoring
mvn spring-boot:run -pl metrics-calculator
.venv/bin/python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

If the detection service writes M4 exports somewhere other than `detection-and-refactoring/target/rmt-ai-shadow-observations.jsonl`, pass that path explicitly to the runner with `--shared-export-path`.

## How To Run

Dry run:

```bash
./experiments/run-benchmark.sh --dry-run
```

Full benchmark:

```bash
./experiments/run-benchmark.sh --run-id tcc-benchmark-01
```

Threshold / performance experiment with the default profile:

```bash
export RMT_AI_EXPERIMENT_PROFILE=default
./rmt.sh all
./experiments/run-benchmark.sh --run-id tcc-default-profile-01
```

Threshold / performance experiment with a lower Template Method threshold:

```bash
export RMT_AI_EXPERIMENT_PROFILE=low-template-threshold
./rmt.sh all
./experiments/run-benchmark.sh --run-id tcc-low-template-threshold-01
```

Threshold / performance experiment with explicit per-pattern thresholds:

```bash
export RMT_AI_EXPERIMENT_PROFILE=per-pattern-threshold
export RMT_AI_THRESHOLD_TEMPLATE_METHOD=0.10
export RMT_AI_THRESHOLD_STRATEGY=0.55
export RMT_AI_THRESHOLD_FACTORY_METHOD=0.20
./rmt.sh all
./experiments/run-benchmark.sh --run-id tcc-per-pattern-threshold-01
```

Reuse existing compiled evaluator classes:

```bash
./experiments/run-benchmark.sh --run-id tcc-benchmark-01 --skip-eval-build
```

## Run Output Layout

Each execution creates `experiments/runs/<run-id>/` with:

- `README.md`: run summary with configuration, success/failure counts, and output inventory.
- `config.env`: frozen run configuration for reproducibility.
- `run.log`: global runner log.
- `project-results.csv`: one row per benchmark project.
- `inputs/benchmark-projects.csv`: manifest snapshot used by that run.
- `logs/<project_id>.log`: per-project upload and polling logs.
- `shadow-jsonl/<runtime-upload-id>.jsonl`: per-project M4 export filtered by runtime `project_id` and deduplicated by `trace_id + entity_id`.
- `shadow-aggregate.jsonl`: aggregate M4 export rebuilt as the union of all per-project JSONL files.
- `shadow-jsonl-report.txt`: validation report with total records, unique records, unique trace IDs, and duplication rate.
- `evaluation/`: M5 outputs generated by `rmt-shadow-eval.sh`.

When available, the shadow JSONL and M5 outputs also include:

- `experiment_profile`
- `template_method_threshold`
- `strategy_threshold`
- `factory_method_threshold`
- `ai_analysis_time_ms`
- `project_processing_time_ms`
- `average_candidate_analysis_time_ms`

If duplication is detected after per-project filtering and deduplication, the runner fails the run and skips M5 evaluation.

## TCC Chapter 4 Mapping

- `shadow-jsonl/*.jsonl`: raw M4 shadow observations used as the experimental base corpus.
- `evaluation/shadow-evaluation-overall.csv`: overall benchmark agreement/disagreement metrics for Chapter 4 aggregate tables.
- `evaluation/shadow-evaluation-by-project.csv`: per-project breakdown for project-level discussion.
- `evaluation/shadow-evaluation-by-pattern.csv`: pattern-level comparison across Strategy, Factory Method, and Template Method.
- `evaluation/shadow-evaluation-discordant-observations.csv`: disagreement inspection material for qualitative analysis.
- `evaluation/shadow-evaluation-failures.csv`: service and transport failure accounting.
- `README.md` plus `project-results.csv`: execution protocol evidence showing date, configuration, project count, and success/failure status for reproducibility.
